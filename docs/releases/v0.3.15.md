# mtty v0.3.15

[简体中文](https://github.com/mttydev/mtty/blob/main/docs/releases/v0.3.15.zh-CN.md)

v0.3.15 is a patch for the inline IME composition. The composition block and
the OS candidate window used to follow the pane's live cursor, so while a
full-screen program painted they were drawn wherever that paint had reached and
jumped around the pane. They now stay at the cursor of the last complete frame.

## A composition that stays where you type

Output from a pane is drained per UI frame with a bounded budget (64 KB / 4 ms).
A full-screen program's frame can be bigger than that, and then the widget
paints a partial frame: the live cursor is wherever the paint has got to. The
IME composition block and the candidate window are positioned at that cursor,
so both were drawn mid-pane and moved with every repaint — most visibly while
typing, when each keystroke repaints the program.

The terminal now remembers the cursor as of the last drain that left no output
queued, and the cursor-anchored overlays use it. A drain that finishes the queue
still moves the anchor every UI frame, so the block follows the caret as you
type; a burst that spans several drains keeps the last settled position until
the queue is empty, which is the frame's own cursor.

Synchronized output (`?2026`) would already prevent this, but Windows' ConPTY
re-encodes the screen and does not pass those markers through, so a stable
anchor is what we can hold.

## Verification

`cargo check -p mtty-core` and `cargo test -p mtty-core` (96 passed, 1 ignored).
The widget change is a one-line call of the new accessor at the two overlay
sites; the release build compiles it for every platform.
