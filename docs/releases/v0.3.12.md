# mtty v0.3.12

[简体中文](v0.3.12.zh-CN.md)

## One grid for the press and the motion

v0.3.11 anchored each pane's cell grid to the card's bottom edge, and its notes
said every hit test reads that anchored grid. One did not: the press that
anchors a selection still read the card's inner top, while the motion that
extends the selection read the grid. The difference between the two is the
height the row count does not use — up to one cell — which now sits **above**
the first row, inside the card's top padding.

A point in that band counted as the first row on press and as no row on motion.
A click therefore painted **two blank rows** of selection: one from the press
column to the end of its line, the next from the line start to the same column.
The fix makes press, motion, and the pane context menu hit-test the same
anchored grid, so a click lands on the cell the renderer painted.

## A click is not a selection

A press that never leaves its cell used to leave a one-cell selection behind.
The selection now starts only when the pointer crosses into another cell, so a
still click selects nothing and writes nothing to the clipboard.

## Also

- The remainder above the grid is part of the card's top padding, so it belongs
  to no row: a press there anchors nothing until the pointer moves into a row.
