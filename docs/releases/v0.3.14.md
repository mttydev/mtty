# mtty v0.3.14

[简体中文](v0.3.14.zh-CN.md)

## Full-width punctuation reaches the pane

Some IMEs commit a character without ever starting a composition:
Microsoft Pinyin's full-width quotes are the common case. Windows posts
`WM_IME_CHAR` straight to the window for those commits. winit 0.30 has no
handler for that message, and its `WM_CHAR` branch drops characters with
no matching key press, so the commit never became an event — composed
Chinese reached the pane through `Ime::Commit`, while every quick-committed
punctuation mark was silently lost.

The window now subclasses itself and observes `WM_IME_CHAR`: each committed
character is forwarded through the same delivery path as a composition
commit — focus, read-only, and editor routing all unchanged — and the
message is swallowed so it cannot re-emerge as a duplicate `WM_CHAR`.
Surrogate pairs (an IME committing an emoji) arrive as two messages and
are paired before delivery.
